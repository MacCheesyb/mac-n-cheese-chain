# R0NI Testnet — multi-node simulator

Prototype only — not audited, no real value, do not use for real funds.

## What this is — and what it is not

- **Simulated, not real VMs.** Three nodes run as separate OS processes
  on ONE Linux VM, each with its own data directory, talking over
  localhost HTTP (127.0.0.1:8001–8003). Docker was not available on
  this machine and no real VMs were created. Say so whenever you
  quote the numbers.
- **Mac's address is inbound only.** Mac's address is
  `R0NI-ebeb98a5aeea016f49e6abf1c8b1e492317a102d`. The testnet does
  NOT have his private key, never asked for it, and never signs a
  transaction from his address. Test transactions are: test wallet
  → Mac's address, and test wallet → test wallet (fully signed by
  the test wallets). A transaction *from* Mac's address requires
  Mac to sign it in his own wallet app — it is recorded as such
  in `analytics.json`, not simulated.
- **Test funds are test-only.** Genesis allocates 1,000,000 test
  R0NI to each of three freshly generated test wallets. Those keys
  live only in `/tmp` for the run and are never committed.

## Files

- `node.py` — the node: EvoHash-11 (imported from `roni_wallet.py`,
  the exact chain, not a reimplementation), PoW difficulty `0000`,
  mempool, Ed25519-signed transactions verified before acceptance,
  localhost P2P gossip (transactions + blocks), longest-valid-chain
  sync, JSON HTTP API (`/chain`, `/mempool`, `/status`,
  `/balance?address=…`, `POST /tx`, `POST /block`).
- `run_testnet.py` — starts 3 nodes, runs 20 phase-1 transactions,
  a 30-transaction TPS burst, a node-restart sync test, and four
  security tests, then writes `analytics.json` / `ANALYTICS.md`.
- `genesis.json` — the testnet genesis block (generated per run;
  addresses only, no private keys).
- `analytics.json`, `ANALYTICS.md` — measured results from the run.

## Spending from Mac's genesis address — the only permitted path

The testnet never holds, asks for, or uses the genesis private key.
A transaction *from* Mac's address can only arrive as a signed
transaction he creates himself in his own wallet app:

1. Mac signs the transfer in standalone `wallet-app.html` (his key
   never leaves his device).
2. He provides the signed transaction JSON.
3. `testnet/accept_signed_tx.py signed-tx.json` verifies the
   signature against the sender's public key and submits it to a
   node, which re-verifies it before acceptance.

Recommended path: Mac makes **one** signed transfer in-app from
genesis to a fresh disposable test wallet (small amount). The
testnet then uses *that* disposable test wallet's keypair
(test-only, generated by the testnet) for further spending tests
— never the genesis key.

## Run it

```bash
/tmp/r0ni-testnet-venv/bin/python testnet/run_testnet.py
```

Requires a venv with `cryptography` (the script uses
`/tmp/r0ni-testnet-venv`). Node 1 mines; nodes 2–3 sync.
